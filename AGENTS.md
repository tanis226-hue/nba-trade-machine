# Project: NBA Trade Machine

## Commands
- Test: `npm test` (vitest). Typecheck: `npx tsc --noEmit`. Build: `npm run build`. Lint: `npm run lint`.
- DB scripts read `process.env` only — pass the env file: `npx tsx --env-file=.env.local scripts/migrate.ts` (and `scripts/import.ts`). `npm run migrate` / `npm run seed` alone will fail with "Set DATABASE_URL".
- Stats refresh (residential IP only — stats.nba.com blocks cloud IPs): `npx tsx scripts/stats/pull.ts`.

## Gotchas (things that have bitten us)
- **The app runs against the live Neon DB** (`DATABASE_URL` in `.env.local`). `hasDb()` true → queries hit Neon; otherwise the filesystem fallback (`lib/data/local.ts`) reads `data/seed` < `scripts/scraper/out` < `data/overrides`. New queries must degrade gracefully (try/catch → local) so a not-yet-migrated column never 500s the page.
- **Migrations**: `scripts/migrate.ts` is tracked + idempotent (`schema_migrations`, keyed by filename). Migration SQL must avoid `;` inside comments and reserved keywords as column names (e.g. `window` → use `news_window`). Additive only (`add column if not exists`). Two `0009_*` files exist (vote-dedupe + trades-owner) — next migration is `0010+`.
- **Accounts (Phase 2)** are off by default and degrade gracefully: `lib/auth.ts` `authEnabled` reads `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`. With no Clerk keys there's no `ClerkProvider`/middleware/Save/My-Trades and the board is Phase-1 local-only. Activate by setting `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` + `CLERK_SECRET_KEY` in `.env.local`. Saved trades reuse the `trades` table (`user_id`/`title`/`updated_at`, migration `0009_trades_owner.sql`); the server route derives `userId` from the Clerk session, never the request body. **Keep `middleware.ts` (NOT `proxy.ts`)** — Next 16 renamed the convention but `proxy` is nodejs-only and Clerk's `clerkMiddleware()` needs the edge runtime, which only `middleware.ts` keeps.
- **Refresh-safety**: the board persists to `localStorage` (`trade-machine:board:v1`) via Zustand `persist` (`skipHydration` + an `onFinishHydration` gate in `TradeBoard`). `partializeTradeState` persists only working state (no actions, no `compareIds`). `contracts` is derived from teams+rosters so a restored board rebuilds cap sheets with no extra wiring.
- **Base season is `2026-27`** (`SEASON_2026_27` in `lib/cba/constants.ts`, store default, `selectValidation`). 2025-26 stays as a prior year. Projected 26-27 cap landmarks are marked `// PROJECTED` — verify when official.
- **CBA engine** is pure + fixture-tested under `lib/cba/`. Rules are `(ctx: RuleContext) => TradeFinding[]` registered in `lib/cba/rules/index.ts`. Only `matchingRule` may *legalize* a takeback (cap-room/TPE/min/non-sim); the rest are additive. Ignore Stay assets (`fromTeam===toTeam`) everywhere.
- After UI changes, verify in the browser (preview MCP). React state updates are async — click in one eval, read the DOM in the next.

## Data sources
- Salaries/options: Basketball-Reference scrape (`scripts/scraper`). Player value (Game Score) + bio + headshots (nba_id) + **age** (leaguedashplayerbiostats, joined by person id) + **2026 rookies**: `stats.nba.com` (`scripts/stats/pull.ts`, residential IP only). Rookies inject into `data/overrides/{players,contracts}.json` at rookie-scale.
- **Roster moves / pending trades**: use the codified loop, don't hand-edit. Author `scripts/txns/pending.json` (schema in `scripts/txns/README.md`), then `npm run txns:apply` (writes the `players.json` overrides by matched `id` + prepends `RECENT_TRANSACTIONS` and bumps `DATA_AS_OF` in `lib/data/freshness.ts`) and `npm run txns:check` (dup-id / phantom-player / feed guard) before `npm run seed`. Straight trades reflect; free-agent signings + sign-and-trades are authored `reflect:false` (no `2026-27` salary yet - the scrape backfills, then they render). `scripts/txns/ROUTINE.md` is the schedulable prompt (daily offseason / weekly in-season). The live Neon app shows moves after `npm run seed`; the local fallback reflects them immediately. Pick-ownership legs (`draft_picks.json`) still lag player moves.
- **Draft picks are REAL** future ownership (drafts 2027-2033) as of Jun 2026, web-researched (ESPN/Fanspo/reporting) into `scripts/picks/_raw.json` → `scripts/picks/build.ts` → `data/seed/draft_picks.json`. `draft_picks` is full-replace: `import.ts` runs `DELETE FROM draft_picks` before re-loading. Protection wording is approximate; refresh by re-running the pick-research workflow + build.
- **CBA-truth data now curated** (web-researched + adversarially verified, in `data/overrides` / `data/seed`): trade kickers (`contracts.trade_bonus_pct`, ~40 players; matching/hardCap rules read it), no-trade clauses (`contracts.no_trade_clause`: LeBron + Lillard), open TPEs (`team_exceptions`, ~22), non-/partial guarantees (`contracts.guarantee_status`, ~17), years-of-service (`players.years_of_service`, from the stats pull's `FROM_YEAR`; drives RFA detection), and 2025-26 final standings as the projected-record baseline (`team_projected_record`; `getProjectedRecords` ranks win% → draft slot, feeding pick value + the pick-chip conveyance display). Refresh kickers/NTCs/TPEs/guarantees via the research-workflow pattern; refresh YOS by re-running `scripts/stats/pull.ts` (residential IP) then `npm run seed`.
- Still missing: **signed-via / Bird rights** — no clean free source (Spotrac is Cloudflare-blocked). Best derived from team tenure (consecutive seasons on a team), which needs per-player acquisition dates we don't track in bulk (`tradeRestrictions.ts` has a few curated `acquiredDate`s). Exact kicker percentages / fine print are Hoops-Rumors-grade approximate; the Spotrac API or manual entry would sharpen them.
